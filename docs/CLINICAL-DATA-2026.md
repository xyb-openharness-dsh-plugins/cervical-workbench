# 宫颈癌 2026 临床研究线索：来源与口径

> 本文只说明"这 14 条线索从哪来、什么时候核对的、哪些渠道**没查**"。
> 它不是入组建议，也不判断哪条试验更好——工作台只做"把登记信息抄清楚、把问题带到门诊"。

- 采集日期：**2026-10-21**
- 每条记录的核对日期（`trials.last_verified`）：**2026-10-21**
- 覆盖窗口：首次登记（StudyFirstPostDate）在 **2026-01-01 → 2026-10-21**

## 一、来源终态（先说没查的）

| 渠道 | 本轮状态 | 说明 |
| --- | --- | --- |
| ClinicalTrials.gov（API v2） | **已采集** | 列表 + 单条详情都取了，原始响应留在 `research/cervical-cancer/` |
| 国家药监局药物临床试验登记与信息公示平台 | **探测过 · 被 WAF 拦** | 脚本请求返回 HTTP 202（25 KB 挑战页，无登记锚点），判定不可采集；**本轮覆盖未知** |
| 中国临床试验注册中心（ChiCTR） | **探测过 · 被 WAF 拦** | 脚本请求返回 HTTP 405（2.6 KB），判定不可采集；**本轮覆盖未知** |
| WHO ICTRP | **未采集** | 聚合库，与上两项重叠 |
| 会议摘要 / 药企管线页 | **未采集** | 只做登记信息，不引用未发表的疗效口径 |

**所以：这 14 条不是"2026 年宫颈癌试验的全集"，只是 CT.gov 一个通道在窗口内的一个子集。**
界面上的措辞固定为「2026 线索 · N 条 · 真实登记摘录，状态未核实」，
不写「全部」「最新」「已穷尽」。

> 两个国内平台不是"忘了查"，是**查过、拦住了**。`research/cervical-cancer/fetch-cn-registries.mjs`
> 记录`{checkedAt, status, bytes, blockedReason, collectable:false}` 到
> `research/cervical-cancer/cn-registry-attempt.json`，**只存判定，不复制站点内容**。
> 想补这两块覆盖，只能人工检索后逐条手录（登记号、题目、状态、核对日期），
> 不能把"脚本跑不通"写成"没有相关试验"。

## 二、抓取与筛选

1. 列表接口（`research/cervical-cancer/raw-2026.json`，**158 条**）：
   `GET /api/v2/studies?query.cond=cervical cancer&filter.advanced=AREA[StudyFirstPostDate]RANGE[2026-01-01,2026-10-21]&pageSize=300`
2. 人工按"宫颈癌患者真正会遇到的岔路口"筛到 **14 条**，覆盖 13 个话题标签：
   新辅助免疫 ×3、新辅助 ADC ×1、复发 ADC ×2、复发联合 ×1、复发一线 Ⅲ 期 ×1、
   前病变/生育保留 ×1、生育保留 ×1、后装技术 ×2、放疗长期影响 ×1、放疗方案 ×1、营养支持 ×1。
3. 单条详情（`research/cervical-cancer/trials-detail.json`，204 KB，14 条）：
   **不用 `?fields=`**——单条详情接口的字段白名单与列表接口不同，写错一个字段整个请求 400。
   直接取完整记录，脚本 `research/cervical-cancer/fetch-detail.mjs`（250 ms 节流）可重跑。

## 四、写进界面时必须守的四条

1. **注册节点 ≠ 临床结果**。上表全部是登记信息：没有 ORR / PFS / OS。
   界面不出现任何疗效数字，也不把"已获批临床""招募中"当作进展。
2. **状态会变**。`尚未招募 / 招募中` 是 2026-10-21 的快照，界面必须带核对日期，
   措辞是「以登记页与研究中心为准」，不写「现在还能入组」。
3. **不替患者判断适配**。入选/排除标准原文太长，工作台只提供「入组问题」清单
   （我能参加吗 / 需要哪些检查 / 要跑几趟 / 影响现在治疗吗），由患者带去门诊问。
4. **国外中心要标出来**。14 条里 5 条在境外（意大利、荷兰、美国、泰国、埃及），
   界面显示申办单位原文，不做"国内可参加"的暗示。

## 五、复现方式

```bash
# 1) 重新抓列表（需联网；窗口改这里）
node research/cervical-cancer/fetch-list.mjs      # 生成 raw-2026.json
# 2) 重抓 14 条详情
node research/cervical-cancer/fetch-detail.mjs    # 读取 raw 里筛出的 NCT，生成 trials-detail.json
# 3) 写回演示库与原型快照
node demo/build-demo-data.mjs
node scripts/check-demo-columns.mjs
# 4) 复跑国内两个平台的"是否可采集"探测（退出码 0=可采集，3=都被拦）
node research/cervical-cancer/fetch-cn-registries.mjs
```

`trials` 表字段：`nct_id`（主键）/ `title` / `phase` / `status` / `sponsor` / `topic` / `last_verified` / `url`。
`topic` 是界面筛选标签的唯一来源；`last_verified` 缺失会让"状态未核实"那句话失效，测试会拦。
